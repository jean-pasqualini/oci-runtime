technical_name: state-persistence
description: Persist container metadata to `<root>/<name>/state.json` at create time and derive `domain.ContainerState.Status` on Load by combining `exec.fifo` presence with `/proc/<pid>` liveness. Unlocks the dead refusal check in `delete.go` (running container cannot be deleted) and gives future handlers (stop, list, kill) a real Status to read.

decisions:
- (2026-05-19) approach: hybrid (runc-style) — persist {pid, bundle, created} in state.json; derive Status on Load via exec.fifo + /proc/<pid> checks. Status is NOT persisted.
- (2026-05-19) file location/format: `<root>/<name>/state.json`, standard library `encoding/json`. No new dependency.
- (2026-05-19) status set: `created`, `running`, `stopped`. Add `StatusCreated` + `StatusStopped` constants alongside the existing `StatusRunning`.
- (2026-05-19) pid source: persist `Pid` in state.json at create time (`containerCommand.Process.Pid` is already available in createHandler). Independent of optional `--pid-file`.
- (2026-05-19) created vs running signal: runc trick — start handler removes `exec.fifo` after sending the kick byte. Load: `exec.fifo` present → `created`; absent → check `/proc/<pid>` for `running` vs `stopped`.
- (2026-05-19) existence gate moves from `exec.fifo` to `state.json`: today `container.Manager.Load` returns "container not found" when `exec.fifo` is missing, but after task 5 `exec.fifo` is removed at start. Use `state.json` as the canonical existence marker so delete still works on running/stopped containers.

- Task 5 (2026-05-19): Wired `startHandler` to unlink `exec.fifo` right after the kick byte is delivered (`internal/app/start.go:42-44`). With this in place the Load Status derivation written in Task 3 becomes live end-to-end: `exec.fifo` present → `created` (create without start), absent + `/proc/<pid>` alive → `running` (post-start), absent + no `/proc/<pid>` → `stopped` (init exited). The dead "container is running" refusal path in delete-container Task 7 is now reachable — `delete` on a started container will hit `domain.StatusRunning` in Load and refuse, while a stopped/created container goes through cleanup.
